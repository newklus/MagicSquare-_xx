## 1) 주제 한 문장 (Mom Test 기반, 솔루션 최소화)

**「4×4 부분 마방진(빈칸 2, 1~16, 합 34)에서 행·열·대각선 조건을 빠짐없이 판정할 수 있는 검증 기준과, 그 기준을 반복 확인하는 테스트 루프를 만든다.」**

- 불편 중심: **판정 불확실성·20분 낭비·LLM 의존 확인**을 겨냥
- 솔루션 최소화: "풀이 프로그램/UI/자동 채우기"가 아니라 **판정 기준 + 확인 루프**만

---

## 2) R-G-I-O

| | 내용 |
|---|---|
| **Role** | Mom Test 증거를 코드로 재현하는 개발자 — 검증 함수와 테스트만 작성 (풀이·UI는 하지 않음) |
| **Goal** | 4×4 격자 입력에 대해 **행 4 + 열 4 + 대각선 2 = 10개 줄**의 합 34 여부를 판정하고, **어느 줄이 틀렸는지** 알려준다 |
| **Input** | `4×4` 정수 배열. `0` = 빈칸 2개. 나머지는 `1~16` 각 1회. 예: `[[16,3,2,13],[5,10,11,8],...]` |
| **Output** | `{ "valid": bool, "failed_lines": ["row_2", "diag_main", ...], "line_sums": {...} }` — LLM 없이 즉시 판정 가능한 구조 |

---

## 3) 성공 기준 3개 (Mom Test 증거와 연결)

| # | 성공 기준 | 연결 증거 |
|---|-----------|-----------|
| **SC1** | **10개 줄**(행·열·대각선) 검증 테스트가 통과하고, 대각선만 틀린 격자에서 `failed_lines`에 대각선이 포함된다 | ① 대각선 빼먹어 20분 낭비 — "대각선도 반드시 검사"를 코드로 고정 |
| **SC2** | 틀린 줄이 **구체적으로** 반환되어, 전체 격자를 비우지 않고 해당 줄만 재검산할 수 있다 | ② 처음부터 다시 — "어디가 틀렸는지"를 알면 전면 재시작 비용 감소 |
| **SC3** | `pytest` 한 번으로 판정 결과 확인 가능. 정답/오답/빈칸 포함 케이스 ≥3개 | ③ LLM 확인·피로 중단 — 외부 AI 없이 즉시 확인 → 세션 이어가기 가능 |

## 4) 표면 문제 — 이번 프로젝트에서 **하지 않을 것**

> STEP 1 표면 문제: 「4×4 부분 마방진 **검증·풀이 프로그램**을 만들면…」

| 하지 않음 | 이유 |
|-----------|------|
| **자동 풀이·빈칸 채우기·힌트 생성** | 진짜 문제는 "못 푸는 것"이 아니라 **판정·확인 비용** |
| **웹/앱 UI, 공유·설명 기능** | 세션 3 범위 밖. Mom Test "공유" 카테고리는 다음 단계 |
| **LLM 연동 답 확인** | 증거 ③가 보여주는 **회피 경로**를 제품화하지 않음 — 대신 테스트 루프로 대체 |
| **3×3·5×5·빈칸 3개 등 일반화** | MagicSquare_XX 스펙(4×4, 빈칸 2)에만 집중 |
| **"완성된 검증·풀이 프로그램" 마케팅** | Mom Test 위반 — 이번 세션 산출물은 **Rule + Command + Test Loop** |

## 5) 8계층 — 이번 세션에서 만드는 것

> 세션 1–2: Mom Test, 주제, R-G-I-O (완료)  
> **세션 3: Rule → Command → (Skill) → Test Loop**  
> 이후 세션: Prompt, Report, App 등 (미착수)

### Rule (항상 적용 제약)

**파일 예:** `.cursor/rules/magic-square-xx.mdc`

```
- MagicSquare_XX 스펙: 4×4, 0=빈칸 2개, 1~16 각 1회, 행·열·대각선 합=34
- 검증 시 반드시 10개 줄 모두 검사 (대각선 2개 포함 — 빼먹지 말 것)
- 풀이/자동 채우기/UI 구현 금지. validate + test만
- 실패 시 failed_lines에 줄 이름 반환 (row_0, col_2, diag_main 등)
- TDD: 테스트 먼저 → 구현 → pytest green
```

### Command (슬래시로 실행하는 워크플로)

**파일 예:** `.cursor/commands/validate-grid.md`

```
/validate-grid
→ src/validate.py의 validate_grid(grid) 실행
→ pytest tests/test_validate.py -v
→ 실패 시 failed_lines 출력, SC1~SC3 체크리스트 표시
```

### (Skill) — 선택

**파일 예:** `.cursor/skills/magic-square-verify/SKILL.md`

- **언제 로드:** "마방진 검증", "합 34 확인", "대각선" 키워드
- **내용:** 10줄 검증 순서, 실패 격자 예시 3개, Mom Test SC1~SC3 매핑
- **역할:** Rule을 매번 붙여넣지 않아도 세션마다 동일 판정 기준 유지

### Test Loop (Red → Green → Refactor)

**파일 예:** `tests/test_validate.py` + `src/validate.py`

| 단계 | 내용 |
|------|------|
| **Red** | 대각선만 틀린 격자 → `valid=False`, `diag_main` in `failed_lines` |
| **Green** | `validate_grid()` — 10줄 합 검사 + `failed_lines` 반환 |
| **Refactor** | 줄 이름 상수·헬퍼 분리, 케이스 3개 이상 (정답 / 행 오류 / 대각선 오류) |
| **Loop** | 코드 수정마다 `pytest` — LLM 답 확인(증거 ③) 대체 |

| 구분 | 빠지거나 어긋난 항목 | 계약(기준) | 워크북 현재 |
|------|----------------------|------------|-------------|
| **API 이름** | 함수명 불일치 | `validate_lines` | §5 Command/Test Loop는 `validate_grid()` |
| **Output · line_sums** | 스키마 미정의 | 10줄 각각의 합을 키로 반환 | Output에 `line_sums: {...}`만 있고 키·값 형식 없음 |
| **Output · line_sums** | SC와 미연결 | `line_sums`는 Output 계약 필드 | SC1~3 어디에도 `line_sums` 검증·언급 없음 |
| **Output · valid** | 불변식 미명시 | `valid=True` ↔ `failed_lines=[]` | Goal에 암시만, SC에 명시 없음 |
| **Goal** | 숫자 집합 검증 누락 | Rule: `0` 2개, `1~16` 각 1회 | Goal/SC는 **10줄 합 34**만 |
| **Input** | 잘못된 입력 처리 | 크기≠4×4, 0≠2개 등 위반 시 반환 | Input 제약만 서술, 오류 시 동작 없음 |
| **Input** | 빈칸(0) 합산 규칙 | 0 포함 줄을 어떻게 합산·판정할지 | `0`=빈칸 2개만 명시 |
| **줄 이름 집합** | 10개 enum 미고정 | `row_0~3`, `col_0~3`, `diag_main`, `diag_anti` | 예시만 — R-G-I-O·SC에 전체 목록 없음 |

| **SC2** | 재검산 수단 | `line_sums`가 핵심 | `failed_lines`만 요구 |
| **SC3** | 케이스 구성 | Output 계약 전 필드 검증 | `pytest` + 케이스 ≥3만 |
